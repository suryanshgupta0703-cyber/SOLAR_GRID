1. PROJECT OVERVIEW & FINAL REVIEW OBJECTIVES
================================================================================
SolarGrid is an autonomous artificial intelligence microgrid management system
engineered to solve the intermittency and economic mismatch ("The Duck Curve")
inherent to residential and institutional rooftop solar photovoltaic (PV) systems.

In typical residential communities, peak solar generation occurs during midday
(10:00 AM – 3:00 PM), while peak human electricity consumption occurs during
morning hours (7:00 AM – 9:30 AM) and evening hours (6:30 PM – 10:30 PM).
Uncoordinated operations lead to solar curtailment or low-value grid feed-in
(Rs 2.50/kWh), while heavy loads draw expensive peak grid power (Rs 8.50/kWh).

SolarGrid solves this by:
1. Forecasting 24-hour generation and community demand using an LSTM + XGBoost
   hybrid ensemble model.
2. Ingesting real-time weather and Global Tilted Irradiance (GTI) via the
   Open-Meteo Solar Radiation API without requiring expensive IoT sensors.
3. Automatically scheduling flexible heavy community loads (EV charging fleet,
   community water pumps, HVAC pre-cooling) into solar surplus hours using a
   Greedy Priority Bin-Packing heuristic.
4. Enforcing strict non-interruptible blocks, operating deadlines, and a 35 kW
   transformer safety threshold.
5. Providing full economic (Rupee savings) and ESG (CO2 mitigated and mature
   trees planted) ledgers in a production-ready Streamlit dashboard.

3. METEOROLOGICAL MODELING, SQLITE PERSISTENCE & REAL-DATA INGESTION
================================================================================
3.1 Synthetic Physics Engine & Weather Variables (data_gen.py):
Constructed using empirical solar geometry equations for offline benchmarking:
- Clear-Sky Irradiance (I_cs): Sinusoidal diurnal arc peaking at solar noon:
  I_cs(t) = max(0, 1000 * sin(pi * (t - 6) / 12))  [W/m²]
- Cloud Attenuation (Beer-Lambert Approximation):
  I_actual(t) = I_cs(t) * [1 - 0.75 * (C / 100)^2] + epsilon
- Photovoltaic Power Output (P_solar): System capacity (50 kW peak),
  temperature derating (-0.4%/deg C above 25 deg C), and inverter loss (95%):
  P_solar(t) = P_rated * (I_actual / 1000) * [1 - 0.004 * (T - 25)] * 0.95

3.2 Dual-Peak Community Demand Modeling:
Superposed Gaussian behavioral lobes representing residential habits:
- Morning Peak (07:00 – 09:30): Water heating, cooking, breakfast prep (15 kW peak).
- Midday Valley (11:00 – 16:00): Low residential occupancy (10-14 kW base load).
- Evening Peak (18:30 – 22:30): HVAC, lighting, entertainment, dining (25 kW peak).
- Base Standby Load: 6.0 kW; Maximum Aggregate Peak: Up to 45.0 kW.

3.3 Relational SQLite Database Architecture (solargrid.db):
- Mode: Write-Ahead Logging (WAL) for high-concurrency read operations.
- Table `historical_energy`: 720 records spanning 30 consecutive days.
  Columns: timestamp, temperature_c, cloud_cover_pct, solar_irradiance_wm2,
           historical_solar_gen_kw, historical_baseline_demand_kw.
- Table `forecasts`: Serialized 24-hour model output history.

3.4 Real-Data Layer: Open-Meteo Solar Radiation API (data_fetcher.py):
To address guide feedback regarding synthetic datasets with zero hardware cost:
- Connects to Open-Meteo REST API (100% free, zero authentication keys needed).
- Ingests Global Tilted Irradiance (GTI), Direct Normal Irradiance (DNI),
  cloud cover percentage, and ambient 2-meter temperature.
- Public functions:
  * `fetch_live_forecast(lat, lon, city)`: Real-time next-24-hour weather.
  * `fetch_historical_archive(lat, lon, start, end)`: Real historical weather.
  * `CITY_PRESETS`: Jammu (32.72°N, 74.85°E), Delhi, Mumbai, Bengaluru, etc.

4. MACHINE LEARNING & DEEP LEARNING FORECASTING ENGINE
================================================================================
4.1 Deep Learning Model: PyTorch Stacked LSTM (models/lstm_model.py):
- Input Layer: 8 features (Temp, Clouds, GTI, Hour_sin, Hour_cos, DoW_sin,
  DoW_cos, DayOfYear).
- Architecture: 2 stacked LSTM layers with 64 hidden units each.
- Dropout: 0.20 between recurrent layers to prevent co-adaptation.
- Fully Connected Head: Linear(64 -> 32) -> ReLU -> Dropout(0.2) -> Linear(32 -> 1).
- Sequence Lookback: 24 preceding hours (t-24 to t-1) to predict hour t.
- Optimizer: Adam (lr = 0.001, weight_decay = 1e-4), MSE Loss function.

4.2 Extreme Gradient Boosting: XGBoost Regressor (models/train_models.py):
- Hyperparameters: n_estimators = 300, max_depth = 6, learning_rate = 0.05,
  subsample = 0.85, colsample_bytree = 0.85.
- Captures abrupt non-linear optical cutoffs (e.g. cloud shading transitions)
  and temperature-dependent residential cooling load correlations.

4.3 Hybrid Ensemble Strategy:
Final Solar Prediction:
  Y_hat_solar = 0.55 * Y_hat_LSTM + 0.45 * Y_hat_XGBoost
Weights were determined via cross-validated grid search. LSTM enforces diurnal
temporal smoothness while XGBoost captures sharp non-linear cloud step-changes.
Demand Prediction:
  Y_hat_demand = Y_hat_XGBoost_demand (driven by temporal encodings & temperature).

6. ENERGY BALANCE & SOLAR SURPLUS IDENTIFICATION
================================================================================
Net Energy Balance:
  B(t) = P_solar(t) - P_demand(t),   for t in [0, 23]
Operational Regimes:
1. Surplus Window (B(t) > 0): Typically 10:00 AM to 3:00 PM, generating up to
   +35 kW of net clean energy. Without scheduling, this energy is exported
   at low feed-in tariffs (Rs 2.50/kWh).
2. Deficit Window (B(t) < 0): Morning and evening periods requiring grid draw
   at expensive peak rates (Rs 8.50/kWh).

7.1 Shiftable Community Load Specifications:
┌───────────────────────┬────────────┬──────────┬──────────┬───────────────┬──────────┐

│ HVAC Pre-cooling      │ 3.5 kW     │ 2 hours  │ 3 (Low)  │ Yes (Split)   │ 16:00    │
└───────────────────────┴────────────┴──────────┴──────────┴───────────────┴──────────┘

7.2 Multi-Constraint Greedy Priority Bin-Packing Algorithm:
1. For Non-Interruptible Appliances (EV Charging):
   Scans all candidate contiguous time windows of length D before deadline.
   Identifies the contiguous window that maximizes solar surplus capture while
   strictly ensuring that total load (base demand + 11 kW) does not exceed
   the 35.0 kW transformer safety limit.
2. For Interruptible Appliances (Water Pump, HVAC):
   Ranks individual candidate hours descending by available surplus B(t).
   Greedily allocates hours until duration is satisfied, respecting transformer
   capacity.
3. Fallback Mechanism:
   If solar surplus is exhausted or insufficient (e.g. severe rain/monsoon),
   remaining required runtimes are placed into the cheapest night off-peak
   tariff hours (23:00 – 05:00 at Rs 4.00/kWh), preventing expensive peak draws.
